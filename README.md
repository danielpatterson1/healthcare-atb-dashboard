# Aged Trial Balance (ATB) Dashboard

**[Open the live dashboard](https://danielpatterson1.github.io/healthcare-atb-dashboard/)** | Built with R, DuckDB, Parquet and R Markdown | **100% synthetic data**

A rebuild of a production AR reporting pattern: one automated report that follows every hospital account from discharge to payment, explains why each open balance is open, and lets anyone drill down to the accounts behind a number and export them to Excel.

> All data in this repository is randomly generated by `R/generate_synthetic_data.R`. No real patients, accounts, payers, facilities or dollar amounts are represented.

## Problem

AR teams need to know where open balances sit, how old they are and what is holding them. In a typical hospital business office that answer is spread across several system extracts, each with its own date formats, payer spelling and duplicate rows. Analysts end up pulling account lists by hand every time someone asks "what is behind this number?"

## Approach

1. **Extract:** a seeded generator produces three messy extracts (encounters, claims, transactions) for about 15K discharges across 12 facilities and 10 payers. It plants text dates, currency strings, inconsistent payer spelling and duplicate transactions on purpose.
2. **Transform (R):** read everything as text, standardize types, collapse payer spelling variants, remove duplicate transactions, roll payments and adjustments up to the account, and derive status (unbilled, billed, denied, underpaid) plus a next step for every open account.
3. **Load (Parquet + DuckDB SQL):** curated Parquet files feed two SQL queries. One builds the aged trial balance; the other rebuilds month end open AR for the last 12 months straight from transaction history.
4. **Validate:** 10 checks run before every render: unique keys, no orphan transactions, balances that tie out, every unbilled account has a reason, and the trend ties to the ATB. Any failure stops the pipeline.
5. **Report:** a flexdashboard with linked filters and an Excel export of exactly the rows on screen.

```
data/raw/*.csv  →  R/etl.R  →  data/curated/*.parquet  →  sql/*.sql (DuckDB)  →  R/validate.R  →  index.html
```

## Stack

R, dplyr, Arrow and Parquet, DuckDB SQL, R Markdown, flexdashboard, Plotly, DT, crosstalk, GitHub Pages

## Results

On the synthetic data set the dashboard surfaces:

* About **$33M** in open AR across about **3K** open accounts
* About **40%** of open AR sitting more than 90 days past discharge, and that share rising steadily over 12 months
* About **20%** of open AR still unbilled, with missing documentation and coding review as the largest holds beyond the standard bill hold window
* Denials concentrated in authorization, medical necessity and eligibility, which account for about two thirds of denied dollars
* All **25** planted duplicate transactions caught, and **10 of 10** data checks passing

What carries over to a real business office: every balance has a reason and a next step, and any chart leads to an exportable account list, so AR teams stop requesting lists from analytics.

## How to run

Requires R 4.3 or later and pandoc (bundled with RStudio or Quarto).

```r
install.packages(c("dplyr", "tidyr", "arrow", "duckdb", "DBI", "rmarkdown",
                   "flexdashboard", "plotly", "DT", "crosstalk"))
```

Then from the project folder:

```bash
Rscript run_pipeline.R
```

This regenerates the raw extracts, runs the ETL and checks, and writes `index.html`. The seed is fixed, so the output is reproducible.

## Project layout

| Path | Purpose |
|:---|:---|
| `R/generate_synthetic_data.R` | Seeded generator for the messy raw extracts |
| `R/etl.R` | Cleaning, rollup, Parquet output and DuckDB queries |

| `sql/ar_month_end_trend.sql` | Month end open AR rebuilt from transaction history |
